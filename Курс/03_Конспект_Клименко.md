## Структура книги

**Часть I. Основные положения теории систем**
1. Сущность системного подхода — системность материи и мышления, определения, классификация систем, эмерджентные свойства, обратная связь.
2. Моделирование систем — ментальные, семантические, математические, статические и динамические модели.
3. Информационный подход — понятие информации, количественные и качественные меры, информационные процессы, элементы теории принятия решений.
4. Системы с управлением — структура, аксиомы, функции управления, принцип необходимого разнообразия, организационные структуры.

**Часть II. Основы системного анализа**
5. Основы системного анализа — принципы, структура исследования, целеполагание, дерево целей, процедура выбора, групповой выбор, ранжирование, парные сравнения.
6. Оценивание систем — теория эффективности, измерительные шкалы, статистика.
7. Процедуры оценивания сложных систем — критерии, показатели качества и эффективности, функция полезности, векторная оптимизация.
8. Проблема выбора — выбор в условиях риска и неопределённости, конфликтные ситуации, системы поддержки принятия решений.
9. Базовая методика системного анализа — формулировка проблемы, структурирование проблематики, конфигурирование, постановка задачи и целей, выбор критериев, генерация альтернатив, ресурсные ограничения, моделирование, синтез решения, реализация.

**Часть III. Системный анализ в управлении**
10. Задачи организационного управления (функции контроля, планирования, прогнозирования). 11. Качество управленческих решений. 12. Общая задача принятия решения и неопределённость.

## Ключевые понятия (из глоссария)

| Термин | Смысл в книге | Как это переводится в работу аналитика |
|---|---|---|
| Система | множество взаимосвязанных компонентов с эмерджентностью | ПО + люди + процессы + данные |
| Эмерджентность | свойство целого, не сводимое к сумме свойств частей | «система делает то, что не делает ни один модуль» |
| Элемент | неделимый (в рамках рассмотрения) компонент | модуль, сервис, роль |
| Связь, структура | вид взаимодействия; совокупность элементов и связей | интеграции, схема архитектуры |
| Чёрный ящик | модель: известно поведение, не известна реализация | контракт API, интерфейс |
| Проблема | противоречие между существующим и требуемым состоянием | «боль» заказчика, GAP |
| Проблемная система / надсистема | система, где обнаружена проблема / внешние системы, заинтересованные в её решении | границы анализа, контекст |
| Цель, целеполагание | желаемое состояние; определение этого состояния | бизнес-цели, BACCM: Need |
| Критерий, показатель | мера и правило оценки альтернатив | KPI, метрики, приёмочные критерии |
| Альтернатива | один из возможных вариантов решения | варианты решения / Solution Options |
| Ограничения | ресурсные и иные ограничения | constraints (бюджет, сроки, законы) |
| Управляемость, наблюдаемость | можно перевести систему в нужное состояние; можно судить о состоянии по выходам | мониторинг, логирование |
| Обратная связь | связь выхода на вход | метрики → улучшения |
| ЛПР | лицо, принимающее решение | спонсор, владелец продукта |
| Риск, неопределённость | потенциальный ущерб; недостаток знаний | управление рисками |

## Базовая методика системного анализа (глава 9) → шаги аналитика

1. **Формулировка проблемы.** Исходная формулировка заказчика — «нулевое приближение». Её надо проверить, дополнить и уточнить.
2. **Структурирование проблематики.** Проблема не изолирована, она входит в совокупность проблем. Надо выяснить, как её решение затронет другие системы.
3. **Конфигурирование проблемы.** Описать окружение: **заказчик, ЛПР, активные участники, пассивные участники, команда аналитиков**. Источники — опросы, интервью, сценарии, коллективная генерация идей. Это прямая основа карты стейкхолдеров.
4. **Постановка задачи и цель.** Сначала «что необходимо сделать», затем «зачем» (цель). У разных сторон разные цели и ценности, и опасность — подмена цели средством (пример: «производить продукцию» вместо «удовлетворять спрос»). Цель может уточняться по ходу анализа.
   > Главный вывод книги: *определить истинную цель гораздо важнее, чем найти лучшую альтернативу*.
5. **Выбор и агрегирование критериев.** Критерии — измеримое отражение цели. Их должно быть разумно мало, родственные критерии объединяют. Целевые критерии можно сравнивать, критерии-ограничения — только соблюдать.
6. **Генерация альтернатив.**
7. **Исследование ресурсных ограничений.**
8. **Моделирование проблемы.**
9. **Синтез решения** (выбор лучшей альтернативы).
10. **Реализация решения.**
